# EDUARDORB WORLD — Release standard

## Naming
Use stable lowercase kebab-case repository names. Use the product's proper name in documentation. Distinguish product version, release status and distribution method.

## Versioning
Use MAJOR.MINOR.PATCH for future releases, with compatibility-breaking, feature and corrective changes respectively. Keep manifest, README, changelog and download page synchronized. Prefer immutable version tags and release assets over links to a moving branch. Do not claim a release or checksum exists until verified.

## Release gate
- Verify source and package provenance, rights to distribute, third-party notices and applicable licenses.
- Check files and Git history for credentials, personal data and private media.
- Run static checks and realistic installation/functionality tests; document what was not tested.
- Describe permissions, privacy, known limitations and any third-party platform risks.
- Publish installation instructions, release notes and a versioned package; verify download and public access.
- Update the product catalog and portfolio.

Free use and private modification are permitted only under the applicable product license. Do not override third-party license rights. Do not claim platform approval without evidence.

Commercial client repositories remain private; link only to authorized live demonstrations. Keep private snapshots and hosting configuration out of public distribution packages.
